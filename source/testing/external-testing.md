# 121开放接口：外部测试说明

配套接口文档1.1.7，整理日期2026-11-20。

测试基础地址：`http://testfcst.chinaptac.com/open-api/v1`。测试和正式使用相同路径、字段和签名规则，凭据分别交付。GitHub Pages只提供文档及文件下载，不处理业务请求。

## 1. 开始前准备

121需交付：测试接口启用通知、clientId、keyId、HMAC密钥、专用121测试账号，以及可用部门、供应商、库位、物料等测试数据。密钥由双方线下安全交换，不从网页获取，不填写数据库账号或员工密码。示例ID不能替代真实测试主数据。

**地址可访问不代表接口已验收。** 2026-11-20对用户查询和部门查询做无签名探测时，得到HTTP 200、正文`{"msg":"认证失败提示","code":401}`，与新协议不符。预期应为HTTP 401，包含`code`、`errorCode`、`message`、`requestId`、`data`，其中errorCode为`AUTH_SIGNATURE_INVALID`。需121核对后端版本、安全链与转发后，以真实签名请求完成验收；此记录未认定根因，也未执行采购写入。

## 2. 导入Postman

1. 下载并导入同目录的`121-open-api-external.postman_collection.json`和`121-open-api-test.postman_environment.json`。
2. 在Postman右上角选择导入的测试环境；填写clientId、keyId、hmacSecret和loginAccount，baseUrl保持测试地址。环境变量优先于集合变量，避免填写后仍被空环境变量覆盖。
3. 先对U01点击Send。集合级Scripts → Pre-request已封装签名，会自动添加鉴权头，无需手算，也不使用Bearer Token。单独导入OpenAPI不具备此脚本。
4. 成功后，从U01的departments选定departmentId；填写测试环境变量，再逐项调用字典。库位请求带projectId筛选，不需要筛选时删除该Query参数；审批人请求已列出全部七种角色。

集合共23个请求：用户查询1个、普通字典11个、审批角色字典7个、采购接口4个。D01是一个接口，按字典及角色展开多个测试请求，不是新增18个业务接口。

## 3. 测试接口清单

下表路径均接在测试基础地址之后；各请求都需HMAC签名。

| 编号 | 方法 | 路径 | 测试目的 |
|---|---|---|---|
| U01 | POST | `/users/verify` | 账号、姓名、ID、手机号、有效成员部门；不存在/停用账号的错误 |
| D01 | GET | `/dictionaries/{type}` | 全部12类字典、分页、部门与项目联动、审批人角色 |
| P01 | POST | `/purchase-drafts` | 创建草稿、返回applyId和明细映射、原请求重复不多建单、供应商/物料错误详情 |
| P02 | GET | `/purchase-drafts/by-source` | 按来源+批次恢复结果，尤其创建超时之后 |
| P03 | GET | `/purchase-drafts/{draftId}` | 查询单据状态及首次同步明细ID映射 |
| P04 | POST | `/purchase-drafts/{draftId}/cancel` | 取消本次未锁单测试草稿；重复取消、锁单拒绝 |
| C01 | POST | 智能化提供的固定测试URL | 121主动发送删除事件，由双方验证接收、验签、去重和重试 |

## 4. 采购测试顺序

1. 先查询字典，填入真实测试ID和物料编码；主单必填项、供应商项目要求以接口文档为准。可选ID不填时省略，不能传空字符串。
2. 使用专用测试订单号sourceOrderId、新UUID syncBatchId、16—160字符idempotencyKey；填写budgetMonth（YYYY-MM）与purchaseDate（yyyy-MM-dd）。测试用户同时作为操作人与发起人。
3. **手动**发送P01，核对HTTP 200、code=200、errorCode=null、status=DRAFT。将返回draftId手动填入测试环境；purchaseOrderNo和draftId均为121的applyId。
4. 原样重发P01，保持正文、批次和幂等键不变，应返回同一ID。每次签名头由脚本自动更新。若超时，先执行P02，不能立刻换新批次。
5. 用P02、P03查询同一张单。details为首次同步映射，不包含121后续新增明细及编辑后的完整数据，不用于完整实时对账。
6. 仅对本次未锁单测试草稿手动执行P04，预期DELETED。锁单后预期409/DRAFT_NOT_EDITABLE；不要用真实业务单测试。未调用P04不会影响创建或查询，但不能完成智能化主动取消。

不要直接对整个集合运行Runner：集合包含创建和取消，会写入及软删除数据。HTTP测试应使用专门的测试数据。

## 5. 删除通知如何测试

C01不是121新增的接收接口。智能化提供固定测试URL及独立反向凭据，121配置后，由121页面删除来源草稿或调用P04触发发送。智能化需按同一算法验签，按eventId去重，按sourceOrderId、syncBatchId、draftId核对关联。可靠处理完成或重复事件返回2xx，推荐204；验签失败或处理失败返回非2xx。

双方需验证：收到通知并清空当前关联；暂时返回非2xx或超时后重试；重复通知不重复处理；旧批次通知不清空新批次。未提供测试接收地址时，不能宣称回调已经验收。测试可约定HTTP，正式使用HTTPS。

## 6. 上线前仍需确认

- 周期：当前接口只接受1—36500整数，并按天标注；需求附件包含0及1.5等值，现有资金成本计算另有月口径。确认单位、0值含义和计算影响后才能验收实际金额，不得直接把1.5截断或把0换成1。
- 映射：供应商对应采购项目；单位对应销售渠道；默认周期按哪个维度匹配，以及多单位多渠道如何选择，仍需明确。不能把采购项目和销售渠道混用。
- 税率：当前主单及明细只支持0、0.06、0.13，不支持需求截图的9%。如9%属于实际业务，需先确认并实现后再验收，不可改传13%。
- 对账：当前查询只返回初始明细ID映射。如需121后续增删改明细后的完整实时对账，需另行确认范围。

错误排查：401看签名与时间；403看scope、用户成员部门与客户端授权；422看message和data的字段/行详情；429按Retry-After等待；网络超时或503先查询本轮结果。创建失败应保存errorCode、message和requestId便于双方排查。
